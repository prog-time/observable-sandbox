# TASK-20261016-fix-unmatched-route-label: Исправить метку route=unmatched у служебных маршрутов FastAPI

**Type:** bug  
**Size:** S  
**Status:** todo
**GitHub Issue:** #1 — https://github.com/prog-time/observable-sandbox/issues/1

## Что делаем
Middleware `observe_requests` в `src/app/main.py` берёт шаблон маршрута из `request.scope["route"]`, но этот ключ проставляет только FastAPI `APIRoute`. Служебные маршруты Starlette (`/openapi.json`, `/docs`, `/docs/oauth2-redirect`, `/redoc`) его не выставляют, поэтому в логах и метриках `http_requests_total` / `http_request_duration_seconds` они получают `route="unmatched"` и сливаются с настоящими 404 на несуществующие пути (пример из Loki: `GET /openapi.json route=unmatched status=200`). Нужно определять шаблон пути для любого совпавшего маршрута, оставив `unmatched` только для реально не найденных путей.

## Пользователь получает
Как **разработчик, разбирающий логи и метрики в Grafana**, я могу **видеть служебные маршруты под их собственным шаблоном пути и отличать их от настоящих 404**, чтобы **алерты и дашборды по `route="unmatched"` отражали только реально несуществующие пути**.

## Готово когда
- [ ] Given запущенное приложение, when выполняется `GET /openapi.json`, then счётчик `http_requests_total{method="GET",route="/openapi.json",status="200"}` увеличивается, а лог-запись `http request` содержит `route="/openapi.json"`
- [ ] Given запущенное приложение, when выполняются `GET /docs` и `GET /redoc`, then они учитываются в метриках с `route="/docs"` и `route="/redoc"` соответственно, а не `unmatched`
- [ ] Given запущенное приложение, when выполняется `GET` на несуществующий путь (например, `/no-such-path`), then ответ 404 и метрика/лог получают `route="unmatched"`
- [ ] Given параметризованный маршрут `PATCH /orders/{order_id}/status`, when запрос идёт на конкретный id, then метка `route` остаётся шаблоном (`/orders/{order_id}/status`), а не фактическим URL — кардинальность не растёт
- [ ] Given регрессионный тест в `tests/test_api.py`, when он запускается на коде до фикса, then падает (получает `unmatched` для `/openapi.json`), а после фикса проходит

## Как делаем
- Вынести определение метки в хелпер (например, `_resolve_route_path(app, scope) -> str`) внутри `src/app/main.py`.
- Сначала использовать `scope["route"].path`, если ключ есть (быстрый путь для `APIRoute`).
- Иначе пройти по `app.router.routes` и вызвать `route.matches(scope)`; при `Match.FULL` вернуть `route.path` (для Starlette `Route` — шаблон, эквивалент `path_format`). Фактический `request.url.path` в метку не подставлять никогда.
- Если совпадения нет — вернуть `"unmatched"`. Поведение для `Match.PARTIAL` (путь найден, метод не тот → 405) зафиксировать по ответу на вопрос ниже.
- Регрессионный тест в `tests/test_api.py`: запросить `/openapi.json`, `/docs` и несуществующий путь, затем прочитать значения через `REGISTRY.get_sample_value("http_requests_total", {...})` из `prometheus_client` (или текст `/metrics`) и проверить метки; сравнивать дельту до/после, т.к. реестр Prometheus глобальный и общий для всех тестов.

## Файлы

- `tests/test_api.py` — регрессионный тест на `route` для `/openapi.json`, `/docs` и несуществующего пути

## Не делаем в этой задаче
- Не меняем набор метрик, имена и состав меток в `src/app/metrics.py`.
- Не отключаем и не скрываем `/docs`, `/redoc`, `/openapi.json` и не исключаем их из метрик (исключение есть только для `/metrics` и `/health`).
- Не переделываем дашборды и алерты в `deploy/` под новые значения меток.
- Не поддерживаем `Mount`/вложенные приложения — их сейчас в проекте нет.

## Вопросы

- ❓ Нужно ли исключать служебные маршруты документации из метрик так же, как `/metrics` и `/health`, или учитывать их как обычные маршруты (по умолчанию — учитываем)?
